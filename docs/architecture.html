📋 Vue d'ensemble

L'application est entièrement statique (hébergée sur GitHub Pages). Il n'y a pas de serveur applicatif : le navigateur communique directement avec Supabase via son SDK JavaScript. Les seuls traitements serveur sont les Edge Functions Deno de Supabase, déclenchées par webhooks pour l'envoi d'emails.

🔄 Flux de données principaux

  • 1
    Signalement d'un essaim — deposer.html → formulaire.js collecte prenom/email/commune/GPS → supabase.from('essaims').insert() → Supabase génère un token UUID → lien de gestion affiché à l'utilisateur
  • 2
    Notification email aux abonnés — INSERT déclenche le webhook Supabase → Edge Function notifier-abonnes interroge la table abonnements par département → Resend envoie un email HTML avec lien de désabonnement tokenisé
  • 3
    Affichage de la carte — annonces.js charge les essaims disponibles depuis Supabase → carte.js crée les marqueurs Leaflet (vert pulsant si < 24h, amber sinon) → stats saison alimentées en parallèle → filtres département + ville appliqués côté client
  • 4
    Clic sur un marqueur — Desktop : popup Leaflet natif / Mobile : ouvrirBottomSheet() via détection window.innerWidth < 768 → contenu partagé construireContenuEssaim() → boutons « Parti » / « Récupéré » appellent gerer_essaim RPC
  • 5
    Clôture via lien email — URL gerer.html?token=UUID → gestion.js charge l'essaim par token → bouton Parti/Récupéré → RPC gerer_essaim(token, statut) → disponible = false en BDD, marqueur retiré de la carte
  • 6
    Désabonnement email — Clic lien email → desabonner.html?token=UUID → RPC desabonner(token) → suppression de la ligne dans abonnements

🛠️ Stack technique

🌐 Hébergement

GitHub Pages — statique, CDN mondial, HTTPS automatique, gratuit

☁️ Backend-as-a-Service

Supabase — PostgreSQL managé, RLS, SDK JS, webhooks, Edge Functions Deno

🗺️ Cartographie

Leaflet 1.9 + tuiles CartoDB Voyager. Markers custom CSS. Autocomplete via geo.api.gouv.fr

📧 Emails

Resend API appelée depuis une Edge Function Deno. Templates HTML inline.

✍️ Typographie

DM Sans (Google Fonts) — moderne, lisible, chargé via @import CSS

⚙️ Build

Aucun build step — HTML/CSS/JS vanilla pure. Pas de npm, bundler ou framework.

🔒 Points de sécurité

  • 🔑
    Gestion sans authentification — Les tokens UUID (128 bits) remplacent les sessions. Impossible à deviner par force brute. Transmis uniquement par email.
  • 🛡️
    Email jamais exposé — L'email du déposant n'est pas retourné par l'API publique. Il est utilisé uniquement dans un mailto: généré côté JS depuis la donnée brute.
  • 🔐
    Row Level Security — La clé anon Supabase ne permet que SELECT sur essaims disponibles et INSERT. Toute modification passe par des RPC SECURITY DEFINER qui vérifient le token avant d'agir.
  • 🌐
    XSS — Tout contenu utilisateur affiché dans le DOM passe par escapeHtml() (création d'un nœud texte via l'API DOM, jamais innerHTML directe sur données brutes).
