Diagramme d’architecture et description technique de la plateforme de partage d’essaims d’abeilles. Site statique hébergé sur GitHub Pages, backend Supabase (PostgreSQL + Edge Functions).

1. Vue d’ensemble

L’application est entièrement statique (hébergée sur GitHub Pages). Il n’y a pas de serveur applicatif : le navigateur communique directement avec Supabase via son SDK JavaScript. Les seuls traitements côté serveur sont les Edge Functions Deno de Supabase, déclenchées par webhooks pour l’envoi d’emails.

Principe Détail

Zéro serveur applicatif

GitHub Pages sert uniquement des fichiers statiques. Pas de Node.js, PHP ni Python.

Backend-as-a-Service

Supabase fournit PostgreSQL, une API REST auto-générée, des politiques de sécurité (RLS) et des webhooks.

Authentification par tokens

Pas de login utilisateur. Les actions sensibles (clôturer un essaim, se désabonner) passent par des tokens UUID 128 bits transmis par email.

Zéro build step

Pas de npm, bundler ou framework. HTML/CSS/JS vanilla pur.

3. Flux de données

3.1. 1 — Signalement d’un essaim

deposer.html
  └─► formulaire.js (étapes 1→2→3 + validation)
        └─► geo.api.gouv.fr (autocomplete commune → coordonnées GPS)
        └─► supabase.from('essaims').insert({...}).select('token')
              └─► Supabase génère token UUID automatiquement
              └─► Retourne le token → lien gerer.html?token=UUID
                    └─► Affiché + bouton Copier dans la confirmation

3.2. 2 — Notification des abonnés

INSERT essaims (trigger webhook Supabase)
  └─► Edge Function notifier-abonnes (Deno)
        └─► SELECT abonnements WHERE departement ILIKE ...
        └─► Pour chaque abonné :
              └─► Resend API → email HTML
                    ├── Lien vers index.html (carte)
                    └── Lien désabonnement : desabonner.html?token=UUID

3.3. 3 — Affichage de la carte

index.html (DOMContentLoaded)
  ├─► initialiserCarte()       → Leaflet + CartoDB Voyager
  └─► chargerEssaims()
        ├─► chargerStats()     → 2 requêtes count parallèles → #stats-barre
        ├─► SELECT essaims (disponible=true, order created_at DESC)
        │     └─► filtre client : age > 7j ignorés
        └─► ajouterMarqueur(essaim, ageHeures) pour chaque essaim
              ├─► Desktop : popup Leaflet natif
              └─► Mobile  : ouvrirBottomSheet() (window.innerWidth < 768)

3.4. 4 — Clôture depuis la carte

Clic bouton « Parti » / « Récupéré » dans popup ou bottom-sheet
  └─► marquerEssaimDepuisCarte(token, statut, btn)
        └─► supabase.rpc('gerer_essaim', { p_token, p_statut })
              ├─► 'ok'        → supprime marqueur + ferme panel + màj compteur
              ├─► 'not_found' → "Déjà clôturé"
              └─► erreur      → réactive boutons

3.5. 5 — Clôture via lien email

URL : gerer.html?token=UUID
  └─► gestion.js → chargerEssaim(token)
        ├─► SELECT essaims WHERE token = ?
        │     ├─► disponible=false → affiche statut final
        │     └─► disponible=true  → afficherGestion() [boutons Parti / Récupéré]
        └─► marquerEssaim(token, statut)
              └─► supabase.rpc('gerer_essaim', ...)

3.6. 6 — Désabonnement

URL : desabonner.html?token=UUID
  └─► abonnements.js → traiterDesabonnement()
        └─► supabase.rpc('desabonner', { p_token })
              └─► DELETE FROM abonnements WHERE token = p_token

6. Sécurité

6.1. Gestion sans authentification

Les tokens UUID (128 bits, gen_random_uuid()) remplacent les sessions utilisateur. Probabilité de collision : mathématiquement nulle. Transmis uniquement par email — impossible à deviner par force brute.

6.2. Email du déposant

L’email n’est pas retourné par l’API publique dans la configuration cible. Il est utilisé uniquement pour générer un href="mailto:…​" côté JavaScript. Il n’est jamais inséré directement dans le DOM.

Pour renforcer la confidentialité, créer une vue Supabase qui exclut la colonne email du SELECT public, et exposer le mailto: via une RPC dédiée.

6.3. Protection XSS

Toutes les données utilisateur affichées dans le HTML passent par escapeHtml() :

function escapeHtml(texte) {
  const div = document.createElement('div');
  div.appendChild(document.createTextNode(texte || ''));
  return div.innerHTML;  // Entités HTML encodées, jamais d'injection possible
}

Aucun appel innerHTML direct sur des données non filtrées.

6.4. Clé anon Supabase

La clé anon est publique par conception. Elle ne donne accès qu’aux opérations autorisées par les politiques RLS. Les opérations sensibles (clôture, désabonnement) passent par des RPC SECURITY DEFINER qui vérifient les tokens avant d’agir.

6.5. Webhook Edge Function

L’Edge Function vérifie un en-tête Authorization: Bearer <WEBHOOK_SECRET> à chaque appel. Le secret est stocké dans les variables d’environnement Supabase (jamais dans le code source).
