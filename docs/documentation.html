1. Introduction

1.1. Contexte et objectif

La plateforme Partage d’essaims permet à des particuliers de signaler la présence d’un essaim d’abeilles sauvage sur leur propriété afin qu’un apiculteur puisse venir le récupérer. L’application résout un double problème :

  • Les essaims abandonnés sans récupération meurent ou créent une nuisance.

  • Les apiculteurs cherchent des essaims locaux pour agrandir leur rucher sans coût.

1.2. Contraintes de conception

  • Pas de serveur applicatif : hébergement statique (GitHub Pages).

  • Pas d’authentification utilisateur — accès par tokens UUID.

  • Zéro dépendance de build (no npm, no bundler, no framework).

  • Stockage gratuit (Supabase Free Tier).

  • Fonctionnel sur mobile (bottom-sheet, géolocalisation GPS).

5.3. Fonctions RPC

5.3.1. gerer_essaim(p_token uuid, p_statut text)

Clôture un essaim en toute sécurité depuis le frontend (popup carte ou page gerer.html).

CREATE OR REPLACE FUNCTION public.gerer_essaim(
  p_token  uuid,
  p_statut text
)
RETURNS text
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
DECLARE
  _id bigint;
BEGIN
  -- Vérifie que le statut est valide
  IF p_statut NOT IN ('parti', 'recupere') THEN
    RETURN 'statut_invalide';
  END IF;

  -- Recherche l'essaim encore disponible
  SELECT id INTO _id
  FROM essaims
  WHERE token = p_token AND disponible = true;

  IF NOT FOUND THEN
    RETURN 'not_found';
  END IF;

  UPDATE essaims
  SET disponible = false,
      statut     = p_statut
  WHERE id = _id;

  RETURN 'ok';
END;
$$;

GRANT EXECUTE ON FUNCTION public.gerer_essaim(uuid, text) TO anon;
Retour Signification

ok

Essaim mis à jour avec succès

not_found

Token inconnu ou essaim déjà clôturé

statut_invalide

Valeur p_statut non reconnue

5.3.2. desabonner(p_token uuid)

Supprime un abonnement email à partir de son token.

CREATE OR REPLACE FUNCTION public.desabonner(p_token uuid)
RETURNS void
LANGUAGE plpgsql
SECURITY DEFINER
AS $$
BEGIN
  DELETE FROM abonnements WHERE token = p_token;
END;
$$;

GRANT EXECUTE ON FUNCTION public.desabonner(uuid) TO anon;

ALTER TABLE essaims ENABLE ROW LEVEL SECURITY;

CREATE POLICY "insertion_publique" ON essaims
  FOR INSERT WITH CHECK (true);

6.2. js/carte.js

Gère la carte Leaflet, les marqueurs, les popups (desktop) et le bottom-sheet (mobile).

6.2.1. Fonctions principales

initialiserCarte()

Crée la carte Leaflet avec tuiles CartoDB Voyager, contrôle zoom en bas à droite.

creerIconeEssaim(ageHeures)

Retourne un L.divIcon avec forme teardrop CSS.

  • Vert + animation pulse pour les essaims < 24h.

  • Amber + ombre légère pour les essaims plus anciens.

  • Badge rouge « NOUVEAU » pour les essaims < 24h.

construireContenuEssaim(essaim, ageHeures)

Génère le HTML du popup/bottom-sheet. Contenu partagé entre desktop et mobile. Protège contre XSS via escapeHtml() sur toutes les données utilisateur.

ajouterMarqueur(essaim, ageHeures)

Crée le marqueur Leaflet et le lie à son popup. Écoute l’événement popupopen : si mobile (window.innerWidth < 768), ferme le popup et ouvre le bottom-sheet.

ouvrirBottomSheet(html) / fermerBottomSheet()

Affiche/masque le panneau glissant en bas d’écran. Anime avec transform: translateY. Bloque le scroll du body pendant l’ouverture.

marquerEssaimDepuisCarte(token, statut, btnClique)

Appelle la RPC gerer_essaim, affiche le résultat inline, supprime le marqueur et ferme le panneau.

filtrerMarqueurs(dept, ville)

Parcourt tousLesMarqueurs et applique addTo/remove selon les filtres actifs.

zoomSurDepartement(valeur)

Appelle Nominatim après 600 ms (debounce) et ajuste le viewport via fitBounds.

7. Fonctionnalités détaillées

7.1. Carte interactive

  • Tuiles CartoDB Voyager — plus lisibles que les tuiles OSM par défaut.

  • Marqueurs personnalisés — forme teardrop CSS, rotation -45°. Couleur verte (frais) ou ambrée (ancien). Badge « NOUVEAU » pour < 24h.

  • Animation pulse — cercle verdoyant qui s’étend et s’estompe sur les nouveaux essaims (CSS @keyframes pulse-marker).

  • Popup desktop — Leaflet natif, largeur max 300px, coins arrondis.

  • Bottom-sheet mobile — panneau glissant depuis le bas (pattern Google Maps), activé quand window.innerWidth < 768. Overlay sombre, handle cliquable.

  • Contrôle zoom — repositionné en bas à droite pour ne pas gêner les boutons.

7.2. Filtrage

  • Par département — <select> avec les 101 départements français (codes + noms). Zoom automatique via Nominatim (debounce 600 ms).

  • Par ville — Saisie libre avec autocomplete geo.api.gouv.fr. Zoom niveau 13 sur la ville sélectionnée.

  • Compteur — Affiche le nombre d’essaims visibles / disponibles, mis à jour à chaque filtre et à chaque clôture.

7.3. Bandeau de statistiques saison

Affiché en vert sous le header sur index.html. Alimenté par deux requêtes Supabase parallèles (count) :

const debut = new Date(new Date().getFullYear(), 0, 1).toISOString();
// Compte total depuis le 1er janvier + sous-total récupérés

Éléments mis à jour : #stat-saison, #stat-recuperes, #stat-disponibles.

7.4. Formulaire multi-étapes

Trois étapes avec indicateur visuel (dots + traits colorés) :

  1. Vos coordonnées — Prénom, email, téléphone

  2. Localisation — Commune avec autocomplete, département auto-rempli, mini-carte Leaflet cliquable + bouton GPS

  3. Détails — Description libre, bouton de soumission

Navigation : boutons « Continuer » (validation) et « Retour » (sans perte de données).

7.5. Alertes email

  1. L’utilisateur saisit email + département dans le panneau #panneau-abonnement.

  2. INSERT dans abonnements (avec gestion du doublon UNIQUE).

  3. Lors d’un nouvel essaim, le webhook Supabase déclenche l’Edge Function.

  4. La fonction cherche les abonnés du même département (matching ilike).

  5. Resend envoie un email HTML avec :

    • Nom de la commune et département

    • Lien direct vers la carte

    • Lien de désabonnement tokenisé

7.6. Gestion de l’état d’un essaim

Trois voies pour clôturer un essaim :

  1. Popup/bottom-sheet carte — boutons inline dans le popup, visibles de tous (pas d’auth, confiance utilisateur).

  2. Page gerer.html — lien reçu à la création, token UUID dans l’URL.

  3. Expiration automatique — les essaims > 7 jours sont filtrés côté client (pas supprimés en base, conservation des stats).

7.7. Confidentialité de l’email

L’email du déposant n’est jamais chargé en masse avec les données de la carte.

  • La vue essaims_publics exclut les colonnes email et telephone.

  • Le rôle anon n’a aucun droit SELECT direct sur la table essaims (REVOKE explicite).

  • L’email n’est récupéré qu’à la demande, via la RPC obtenir_contact_essaim(p_id bigint), uniquement quand l’utilisateur clique sur « Je suis intéressé(e) ».

  • Il transite une seule fois, pour un seul essaim, et sert immédiatement à construire le mailto: en JS. Il n’est jamais inséré dans le DOM.

Ce mécanisme empêche le moissonnage en masse des emails par un simple appel API.

8. Déploiement

8.1. GitHub Pages

  1. Pousser la branche sur GitHub.

  2. Activer GitHub Pages dans les paramètres du dépôt (source : branche main, dossier /).

  3. URL automatique : https://<user>.github.io/<repo>/

git add .
git commit -m "feat: initial deployment"
git push origin main

8.2. Supabase

  1. Créer un projet sur supabase.com.

  2. Exécuter les scripts SQL dans l’ordre :

    supabase/schema_gestion_essaims.sql    # Table essaims + RPC gerer_essaim
supabase/schema_abonnements.sql        # Table abonnements + RPC desabonner

  3. Configurer le webhook : Database → Webhooks → New — Event INSERT sur essaims, URL de l’Edge Function.

  4. Déployer l’Edge Function :

    supabase functions deploy notifier-abonnes

  5. Renseigner les secrets :

    supabase secrets set WEBHOOK_SECRET=<votre_secret>
supabase secrets set RESEND_API_KEY=re_xxxx
supabase secrets set PUBLIC_SITE_URL=https://votre-site.github.io

  6. Copier l’URL et la clé anon dans js/config.js.

9.3. Évolutions possibles

9.3.1. Priorité haute

  • Photo de l’essaim — Upload vers Supabase Storage avec compression Canvas côté client (~200 KB). Auto-suppression à la clôture.

9.3.2. Priorité moyenne

  • Authentification — Login optionnel (email magic link) pour permettre à un déposant de gérer plusieurs essaims.

  • Carte de chaleur — Heatmap Leaflet par département pour visualiser la densité d’essaims.

  • Internationalisation — Support ES/DE pour les régions frontalières.

  • Statistiques avancées — Tableau de bord pour les associations apicoles.

10. Glossaire

Terme Définition

Essaim

Colonie d’abeilles qui a quitté sa ruche et cherche un nouvel habitat. Phase migratoire de 24-72h, récupérable par un apiculteur.

Token UUID

Identifiant aléatoire 128 bits. Sert de clé de gestion sans nécessiter d’authentification.

RPC

Remote Procedure Call. Fonction PostgreSQL exposée comme endpoint REST par Supabase.

RLS

Row Level Security. Mécanisme PostgreSQL limitant les lignes accessibles selon le rôle/contexte.

SECURITY DEFINER

Attribut d’une fonction SQL qui s’exécute avec les droits de son créateur, contournant RLS.

Edge Function

Fonction serverless Deno déployée sur le réseau Supabase, proche des utilisateurs.

Bottom-sheet

Panneau UI qui glisse depuis le bas de l’écran sur mobile (pattern Google Maps).

BaaS

Backend-as-a-Service. Supabase fournit DB, auth et API sans serveur à gérer.

Resend

Service d’envoi d’emails transactionnels avec API REST simple.
